# CloudStrmKit 产品需求文档（PRD）

> 更新日期：2026-11-01
> 版本：v0.1.0
> 状态：草稿（待主人确认）
> 关联：`docs/SPEC.md`、`docs/PLAN.md`

## 一、目标

### 1.1 要解决什么问题

当前使用 SmartStrm（付费）配合飞牛影视与 115 网盘：qB 下载 → MoviePilot 整理并上传 115（本地保留做种）→ SmartStrm 生成 STRM（内容为 SmartStrm 解析地址）→ 飞牛媒体库扫描本地 STRM 目录 → 播放时 302 到 115 直链。

现存问题：

1. **STRM 生成不实时**：只能手动或每天凌晨跑一次，整理完成的影片要等下一轮才能在飞牛中看到，体验断层。
2. **付费且功能冗余**：SmartStrm 需为 302 代理等大量用不到的功能付费；实际只用到"STRM 生成 + 115 直链解析 + 飞牛刷新"三件事。
3. **外网播放链路过长**：为让外网可播，需反代整个飞牛服务，配置复杂且与 FN ID 入口冲突。

### 1.2 本版目标

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 整理完成到飞牛媒体库可见、可播，端到端延迟 ≤ 60 秒（常规 ≤ 10 秒） | 实测时间戳：MP 整理完成日志时间 → 飞牛媒体库出现该影片时间 |
| G2 | 播放走 115 直链 302，NAS 侧仅返回 302 响应（KB 级），不承载视频流量 | 播放时 NAS 网卡出流量观测；插件 302 日志命中 |
| G3 | 局域网 / 公网域名（Lucky 反代）/ FN ID 三种入口下均可播放 | 三端各实测一次，记录结果 |
| G4 | 零新增外部服务：只依赖 MoviePilot 进程 + 现有 Lucky 反代 | 部署清单无新增容器/端口 |
| G5 | 完全替代 SmartStrm 的 STRM 生成、115 直链解析、飞牛刷新三项功能 | 停用 SmartStrm 一周后无缺失 |

### 1.3 明确不做

- Emby / Jellyfin / Plex 的 302 反代与兼容层（原因：主人只用飞牛影视；飞牛 8005 Emby 兼容端点不纳入范围）。
- 115 全盘文件生命周期事件监听（原因：主链路是 MP 整理后上传，事件驱动 + 定时对账已足够；全盘监听是 P115StrmHelper 的主要复杂度来源）。
- 分享链转存、离线下载、FUSE 挂载、签到、阿里云盘、多网盘驱动（原因：场景外）。
- Web 端 H.265 等不支持直连的编码兜底转码（原因：主人确认接受报错，保持纯 302）。
- 突破 FN ID 官方中继带宽限制（原因：飞牛侧机制，无法绕过；高码率走公网域名）。
- 视频内截图 / 刮削增强 / 多用户权限体系（原因：场景外；STRM 方案固有局限）。

## 三、功能需求

### F1 整理完成自动生成 STRM

- **描述**：监听 MoviePilot 的整理完成事件，针对上传到 115 的视频文件，在本地 STRM 目录生成对应 `.strm`。
- **入口**：自动（事件驱动），无人工操作。
- **规则**：
  1. 仅处理 `target_storage` 为配置的 115 存储（默认 `u115`）的整理结果。
  2. 仅处理扩展名在配置视频扩展列表内、且大小 ≥ 配置阈值的文件。
  3. 115 路径 → 容器内 STRM 路径按配置的映射表转换（`path_mappings` 最长前缀匹配）；无匹配则跳过并记录告警。写入使用容器内根目录 `strm_root_local`。
  4. STRM 内容为绝对 URL：`{base_url}/api/v1/plugin/cloudstrmkit/play?f=<索引ID>&sig=<HMAC>&e=<过期时间戳>`。
  5. 文件写入使用临时文件 + 原子重命名，避免飞牛扫描到半写文件。
  6. 同一路径重复整理时覆盖旧 STRM 并更新索引，不产生重复条目。
- **边界**：
  - 事件发生在 MP 异步上下文，生成逻辑必须放到后台执行，不得阻塞事件循环。
  - 整季整理一次可能产生数十个文件，必须合并处理并合并飞牛刷新请求。
  - 115 上传失败/未完成时事件不应触发；若触发但 115 文件不存在，记录失败并交由对账任务补齐。
- **依赖**：`EventType.TransferComplete`；MP 内置 115 存储实例可用。

### F2 飞牛影视媒体库实时刷新

- **描述**：STRM 生成后，调用飞牛影视 API 刷新对应媒体库，使影片尽快出现在飞牛端。
- **入口**：自动（F1 之后）。
- **规则**：
  1. 使用配置的飞牛媒体服务器实例（MoviePilot 媒体服务器配置项），调用其 `refresh_library_by_items` 按目标路径定位媒体库。
  2. 同一批整理在配置的去抖窗口（默认 3 秒）内合并为一次刷新请求。
  3. 刷新失败时降级为全库扫描（`refresh_root_library`）一次；仍失败则记录日志并通知（可选）。
  4. 飞牛实例必须为管理员账号，非管理员时日志给出明确提示。
  5. 刷新前把容器内 STRM 路径换算为飞牛视角路径（`strm_root_fnos`），确保媒体库目录匹配。
- **边界**：飞牛扫描为异步任务，插件只保证"扫描请求已提交"，不等待扫描完成；入库延迟取决于飞牛侧。
- **依赖**：`MediaServerHelper` 可取得飞牛实例；`trimemedia.refresh_library_by_items` 可用。

### F3 302 直链播放服务

- **描述**：接收飞牛客户端对 STRM URL 的请求，校验签名后向 115 换取直链并返回 302。
- **入口**：`GET/HEAD /api/v1/plugin/cloudstrmkit/play`（匿名，无需 API Key）。
- **规则**：
  1. 校验 HMAC 签名与过期时间；不通过返回 403，不泄露文件信息。
  2. 按索引 ID 定位 115 文件；必要时按路径向 115 查询文件详情获取 `pickcode`。
  3. **用请求方 User-Agent 调用 115 开放平台** `/open/ufile/downurl` 换取直链（UA 绑定硬约束）。
  4. 直链缓存键为 `(pickcode, UA)`；命中缓存直接返回，TTL 可配（默认 20 分钟），过期前主动刷新。
  5. 并发控制：同一 `(pickcode, UA)` 只允许一个换链请求在途（锁）；全局换链限频默认 2 QPS，超限排队。
  6. 换链失败（401/403/风控）时按退避策略重试，并在日志中标记风控；连续失败进入冷却。
  7. 返回 `302 Found`，`Location` 为 115 直链；附带 `Content-Disposition` 文件名。
  8. `HEAD` 请求同样返回 302 头，不返回 body。
- **边界**：
  - 不代理视频数据流，不做 Range 处理，不转码。
  - 115 链接失效且刷新失败时返回 502，并在日志记录可追溯信息。
- **依赖**：MP 内置 115 存储授权（access_token）；115 开放平台接口。

### F4 定时对账（补漏与清理）

- **描述**：定时比对 115 媒体库目录与本地 STRM 索引，修正不一致。
- **入口**：定时任务（默认每日 04:30，可配置 cron 或关闭）。
- **规则**：
  1. 递归列出配置的 115 媒体库根目录下视频文件，与索引比对。
  2. 115 有、索引无 → 补生成 STRM。
  3. 索引有、115 无 → 按配置开关删除本地 STRM（默认开启）并清理索引。
  4. 115 路径/大小变化 → 更新索引并重写 STRM。
  5. 对账结果写入日志：新增/删除/更新/失败数量。
- **边界**：115 大目录遍历需限速与分批，避免触发风控；对账与实时事件可能并发，需加文件级锁。
- **依赖**：115 文件列表接口（MP 存储实例）。

### F5 插件配置页

- **描述**：在 MoviePilot 插件配置页提供全部配置项，Vuetify 表单。
- **规则**：配置项见 `docs/SPEC.md` 第 8 节；保存后无需重启即可生效（重新初始化服务与路由）。

### F6 播放日志与可观测性

- **描述**：记录每次 302 请求的关键信息，便于排查。
- **规则**：
  1. 每条记录：时间、来源 IP、UA、文件 ID、是否命中缓存、换链耗时、结果状态。
  2. 插件详情页展示最近 50 条。
  3. 提供手动清理直链缓存、手动触发对账入口。

### F7 手动操作

- **描述**：插件页面提供运维按钮。
- **规则**：
  1. 立即对账（全量）。
  2. 清理失效 STRM（索引中 115 已不存在的条目）。
  3. 清空直链缓存。

### F8 刮削附属文件同步（115 → 本地）

- **描述**：MP 整理时会把 NFO、海报等刮削产物一并上传到 115；飞牛媒体库扫描的是本地 STRM 目录，需要把这些附属文件同步到本地，飞牛才能读取本地 NFO/海报。
- **入口**：自动（随 STRM 生成、随对账）。
- **规则**：
  1. 生成某个视频的 STRM 时，列出该视频在 115 上的**所在目录**，把符合白名单的附属文件复制到本地对应目录（保留文件名）。
  2. 白名单命中条件（满足任一）：扩展名在 `copy_exts` 内；文件名为固定刮削名（`poster`/`fanart`/`backdrop`/`banner`/`logo`/`thumb`/`landscape`/`clearart`/`disc`/`tvshow`/`season`）；文件名以视频文件主名开头。
  3. 只同步小文件（默认 ≤ 10 MB），图片/NFO/字幕均远小于该阈值。
  4. 冲突策略可配：`skip`（本地已存在则跳过，默认）/ `overwrite`（按 115 修改时间覆盖）。
  5. 同步过的附属文件记入索引（标记来源），删除与清理**只针对索引记录过的文件**。
  6. 目录级文件（`tvshow.nfo`、`season.nfo`、`poster.jpg`、`fanart.jpg` 等）一并覆盖，避免剧集缺根部 NFO/海报。
  7. 覆盖整理（同一 115 路径被新文件替换）时，先清理该视频旧的附属文件（索引记录的 + 同目录已无对应 STRM 的同名 NFO/海报），再重新同步，避免旧 NFO 残留。
  8. 提供「清理孤儿附属文件」手动工具：扫描本地 STRM 目录，列出没有对应 `.strm` 的附属文件（仅白名单扩展名），用户确认后删除；用于清理 SmartStrm 时期遗留的 NFO/海报。
- **边界**：
  - 用户手动放入 STRM 目录、非本插件复制的文件，一律不删、不改。
  - 115 目录中超过阈值或扩展名不在白名单的文件不同步（如原盘自带的蓝光目录、样片）。
  - 附属文件同步计入 115 限频队列，不单独提高并发。
- **依赖**：115 目录列表接口；STRM 路径映射（同目录规则）。

### F9 两种运行模式（公网 / 无公网降级）

- **描述**：支持公网直连与无公网降级两种运行方式，适配公网 IP 被回收后的场景。
- **规则**：
  1. 模式 A（默认）：`base_url` 为 MP 公网域名，STRM 内为公网地址，局域网/外网客户端直接请求。
  2. 模式 B：`base_url` 为内网 MP 地址，STRM 内为内网地址；局域网直连，外网经 FN ID 时由飞牛服务端在内网解析并 302。
  3. 切换模式只需修改 `base_url` 并执行「全量重写 STRM」。
- **边界**：FN Connect 不支持代理 MoviePilot 这类第三方/Docker 端口，模式 B 不依赖 FN ID 反代 MP，而是依赖"解析发生在内网侧"；该行为需真机验证（V3）。
- **依赖**：飞牛服务端解析 STRM 内网 URL 的能力（飞牛版本相关）。

> 每条均可判定，证据形式以"命令输出/日志摘录/截图"记录到 `docs/PLAN.md` 或 `docs/CHANGELOG.md`。

| A9 | 三端播放实测 | 局域网 / 公网域名 / FN ID 各播放一次并记录结果（成功或按预期失败） | 实测记录 |
| A10 | 不影响 MP 既有功能 | 插件启用后 MP 整理、订阅、通知正常；禁用插件后链路只退回手动模式 | 运行日志 |
| A11 | 刮削文件同步 | MP 整理一部带 NFO/海报的电影后，本地 STRM 目录出现 `.strm` 与对应 NFO/海报；飞牛读取本地 NFO 后标题/简介/海报正确 | 目录列表 + 飞牛截图 |
| A12 | 不误删用户文件 | 在 STRM 目录手动放入 `manual.nfo` 与一个与本插件无关的 `other.strm`，触发对账与清理 → 两个文件均保留 | 目录列表 |
| A13 | 无公网降级模式 | 切 `base_url` 为内网地址并全量重写后，局域网播放 302 正常；外网 FN ID 播放记录结果（成功或按预期失败） | 日志 + 实测记录 |
| A14 | 覆盖与改名 | 同一影片覆盖整理 → STRM 更新、无重复；115 端改名后对账 → 旧 STRM 删除、新 STRM 生成 | 日志 + 目录对比 |

## 五、非功能要求

| 维度 | 要求 | 判定方式 |
|---|---|---|
| 性能 | 缓存命中时 302 响应 < 50ms；未命中（含换链）< 1s | 播放日志耗时 |

| 可恢复 | MP 重启后索引与配置自动恢复；插件重载无残留线程/路由 | 重启测试 |

## 六、已知限制

1. **Web 端编码**：纯 302 不转码，H.265/部分封装在浏览器无法播放，会明确报错。
2. **FN ID**：官方中继带宽有限，302 是否被飞牛改写为中继地址需实测；高码率优先公网域名。
3. **飞牛入库延迟**：`mdb_scan` 异步，入库时间取决于媒体库规模与飞牛调度。
4. **115 风控**：NAS 换链与客户端拉流的双 IP 特征可能触发风控，靠缓存与限频缓解，无法根除。
5. **无视频内截图**：STRM 方案固有限制。
6. **公网入口被回收**：FN Connect **不支持**代理 MoviePilot 这类第三方/Docker 端口（只代理飞牛已注册服务）。公网 IP 取消后，需切到「内网地址模式」：STRM 写内网 MP 地址，由飞牛服务端（FN ID 中继场景下位于内网）解析并 302，客户端仍直连 115。该模式成立的前提是飞牛服务端会解析 STRM 内网 URL（SmartStrm 当前即此形态，需在 CloudStrmKit 上实测确认）。

## 七、已确认决策与待确认项

### 7.1 已确认（2026-11-01）

1. 对账策略采用 **A：MP 整理事件驱动 + 定时全量对账**（对账频率可配，默认每日一次；如需可调至每小时）。
2. 刮削文件采用 **情况 2：115 → 本地同步**（MP 上传到 115 的 NFO/海报复制到本地 STRM 目录）。
3. 飞牛影视会读取本地 NFO，因此附属文件同步为必需功能。
4. 播放端仅飞牛影视（App / 飞牛播放器 / Web），不做 Emby/Jellyfin/Plex。
